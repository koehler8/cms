## Executive summary

The framework source is unchanged since the last review (`git diff 27e9d71..HEAD` touches only `builder/*` buildmill facets), so this pass re-verified all ~50 prior findings against the code and layered a v1-release lens on top. **Every prior finding is still open** (one reclassified, several escalated on closer reading), and **none of the prior plan's 36 items were implemented.** The v1 tag is a semver commitment measured against a real consumer base — 35 repos import `@koehler8/cms/vite`, and `cms-ext-crypto`/`cms-ext-compliance` deep-import components, composables, and utils — so the work sorts into three buckets: **(1) release blockers** — the publish pipeline itself has no test gate and no tag↔version check (tagging `v1.0.0` on a stale tree ships beta code to `latest`); the exports map advertises a `./plugins/*` directory that doesn't exist; a shipped bin *writes `^1.0.0-beta.27` into consumers' package.json*; the scaffold still pins `beta.15` with web3 env vars; tests only pass because npm auto-installs peers. **(2) Breaking-window items** — default flips and removals that are cheap at a major and expensive after: flip `trimInitialState` on (measured 81%/218 KB per page), remove the obsolete lru-cache postinstall (installed versions contain nothing to patch, and the script can fail consumer installs), namespace browser-storage keys, drop `/admin`, demote `canvas` from hard dependency, move AJV validation out of the browser. **(3) Truth-telling fixes** — tooling that reports success while failing: both validator CLIs always exit 0 without validating anything, the contact form tells visitors "sent" on failure and clears their message, the shard merge exits 0 while shipping a client-shell homepage, and SSG config-load failures produce a green build with an empty `<main>` that the blank-page detector structurally cannot catch. Accessibility also needs a pass before v1 markets AA conformance: `DraftGate`/`NotFound` are currently unthemeable (they consume CSS vars defined nowhere), DraftGate declares `aria-modal` with no focus trap, and reduced-motion coverage is inconsistent across five components.

## Findings

Priorities: **P0** breaks the release event itself · **P1** high value / high risk · **P2** worthwhile · **P3** nice-to-have. Effort S/M/L, risk low/med/high. Prior-review findings (A1–F12) remain open as documented there and in the delta table above; this section adds the **new** findings from this pass.

### R. Release blockers & packaging (new)

- **R1 · P0 · The publish workflow can ship the wrong code at the v1 moment** — `.github/workflows/publish.yml`: checkout → setup-node (`node-version: '20'`, floating) → `npm publish`. No install, no tests, no assertion that the tag matches `package.json` version. Concretely: `git tag v1.0.0 && git push origin v1.0.0` on a tree whose package.json still says `1.0.0-beta.39` publishes **beta.39 to the `latest` dist-tag** (the prerelease branch keys off package.json, not the tag). The release event is exactly when this fires. *Fix:* `npm ci` + `npm test` as a `needs:` gate, assert `"v$(node -p require('./package.json').version)" == "$GITHUB_REF_NAME"`, use `node-version-file: .nvmrc`. Effort S, risk low.
- **R2 · P0 · `cms-migrate-image-variants` writes a beta range into consumer package.json** — `scripts/migrate-image-variants.mjs:36`: `TARGET_CMS_VERSION = '^1.0.0-beta.27'` is written into the consumer's manifest. Run post-1.0, it *downgrades* the site back onto beta resolution. It's a one-time beta.26→27 migration; every site migrated. *Fix:* delete the bin entry + script (and `migrate-to-content-dirs.mjs`, same era). Effort S, risk low.
- **R3 · P1 · All three scaffolds pin beta ranges; the site scaffold couples to a beta extension** — `templates/scaffolds/site/package.json:14` (`^1.0.0-beta.15`), `theme/package.json:19` + `extension/package.json:20` (`^1.0.0-beta.1`), `site/CLAUDE.md:43` prose. The site scaffold also hard-wires `@koehler8/cms-ext-compliance@^1.0.0-beta.4` (`package.json:15`, `vite.config.js:10`) — **cutting cms 1.0 without also cutting cms-ext-compliance 1.0 means every new "stable" site starts on a beta extension.** Plan the two releases together. Effort S (pins) + coordination, risk low.
- **R4 · P1 · Exports-map defects** — (a) `"./plugins/*": "./src/plugins/*.js"` targets a directory that **does not exist**; (b) `"./extensions/*"` maps to `./src/extensions/*.js`, but the file consumers actually want is root `extensions/manifest.schema.json` — four site extension configs bypass the exports map with raw `node_modules` relative paths; (c) `./router`, `./constants/*`, `./utils/siteStyles` have zero consumers. *Fix:* drop (a) and unused entries, add `"./extensions/manifest.schema.json": "./extensions/manifest.schema.json"`, document the ~15 supported specifiers in README. Effort S, risk low (verify fleet grep before pruning). 
- **R5 · P1 · Tests run only by accident of npm peer auto-install** — `vitest.config.js:4` imports `@vitejs/plugin-vue`; neither it nor `vite` is in `devDependencies` (both are peers). Works under npm 10 auto-install; breaks under pnpm/yarn/`--legacy-peer-deps`/`--omit=peer` — and the R1 CI gate would inherit the fragility. *Fix:* add `@vitejs/plugin-vue` + `vite` to devDependencies. Effort S, risk low.
- **R6 · P1 · CHANGELOG isn't release-ready** — no `1.0.0` entry yet; `1.0.0-beta.2`–`beta.7` headings are missing (verify against `npm view @koehler8/cms versions` whether unpublished or just undocumented); CHANGELOG.md is **not in `files`** so it doesn't ship to npm. *Fix:* write the 1.0.0 entry (breaking-change list = the R/B items landed), reconcile the gap, add to `files`. Effort S, risk low.
- **R7 · P1 · The lru-cache postinstall patch is obsolete and should be deleted, not fixed** — supersedes A4's "guard the parse." Evidence in the settled-decisions table. *Fix:* remove `postinstall` + script; run one consumer `build:ssg` without it as the verification gate. Effort S, risk low-med (one verify pass).
- **R8 · P2 · Native/hard deps for one CLI** — `canvas` (node-gyp), `png-to-ico`, `dotenv` are `dependencies` reachable only via `cms-generate-public-assets`. Demote to `optionalDependencies` (or a lazily-imported peer with a clear "install X to use this command" message). Effort S-M, risk med (Amplify preBuild depends on the command — degrade must be loud, not silent). 
- **R9 · P2 · Dead scripts ship in the tarball** — `scripts/check-overflow.mjs` imports `playwright` (not a dependency anywhere; hardcodes the framework's own dist path) and `scripts/migrate-to-content-dirs.mjs` (one-time migration, completed fleet-wide). Both ship via `files: ["scripts", ...]`. Remove. Effort S, risk low.
- **R10 · P2 · Browser-storage keys become a compat contract at v1 — three are unnamespaced** — `locale` (5 call sites), `cookie_consent`, `cookie_consent_timestamp`, `app_session_id` vs. the properly-namespaced `cms_draft_unlocked`. Bare `locale` is a likely collision with site/extension code. Also: `router/index.js:131,148` and `Header.vue:439,446` call `localStorage.setItem` unguarded — throws in Safari private mode (only `useDraftGate` try/catches). *Fix at v1:* namespace with `cms_` + one-time legacy-key migration read; wrap writes. Effort S-M, risk low.
- **R11 · P2 · Draft-gate security posture must be documented at v1** — unsalted SHA-256 of the password ships in the public bundle; gated pages ship full content in hydration JSON; robots `Disallow` lines disclose draft paths (D3). None of this is new behavior — but v1 is when external users start trusting it. One README section: what the gate does and does not protect. Effort S, risk low.
- **R12 · P3 · Eager registry payload** (post-v1) — every bundled component in every bundle; explore non-eager glob + `defineAsyncComponent` resolution with SSG-safe hydration. Effort L, risk med-high.
- **R13 · P3 · Two bins break on Windows** — `cms-ssg-build.js:13` and `cms-migrate-image-variants.js:11` pass bare absolute paths to dynamic `import()` (drive letters parse as URL protocol); the other six correctly use `pathToFileURL`. Moot for R2's bin if deleted; fix `cms-ssg-build`. Effort S, risk low.
- **R14 · P3 · Orphaned shipped assets** — `public/img/preloaders/preloader-{black,white}.svg` ship and are mirrored into every site's `public/` (`vite-plugin.js:412-416`) but referenced by nothing; `Preloader.vue` is an empty shell with copy-pasted "header" comments. Decide: wire them up or delete both. Effort S, risk low.
- **R15 · P3 · `generate-public-assets.js:92` references `scripts/fonts/Inter-Bold.ttf`** — path doesn't exist in the package; the "bundled brand font" branch is dead and silently falls through. Ship the font or remove the branch. Effort S, risk low.
- **R16 · P2 · Published `engines` posture** — see settled-decisions row. Effort S, risk low.
- **R17 · P3 · Fleet docs teach deep `node_modules/@koehler8/cms/src/...` paths** — site-coastalcollective CLAUDE.md, extension READMEs, site-qdoz validation notes. Docs-only today, but they train the habit the exports contract is about to forbid. Post-v1 sweep. Effort S, risk low.

### G. Plugin writes into the consumer's source tree (new)

- **G1 · P2 · `writeSeoFiles` runs at `configResolved` — including plain `vite dev` — and mutates/deletes tracked files** — `vite-plugin.js:861-876` writes `robots.txt`, `manifest.json`, `sitemap.xml` into the site's git-tracked `public/` on every config load, and **`unlink`s `sitemap.xml`** (`:435`) when `site.url` is missing — a config typo during dev silently deletes a tracked file. This is also the root of the hand-edited-robots.txt drift class that `allowAiCrawlers` (beta.39) patched one instance of. *Fix:* write SEO files only for build commands (or gate dev writes behind a flag), never unlink without a logged reason; recommend sites gitignore all three (the scaffold already ignores `public/`). Effort S-M, risk low.
- **G2 · P3 · Crash-orphaned temp files + the broken dev-server flag (F5)** — generated `siteRoot/index.html` + `.cms-entry.js` are cleaned only on graceful exit; a crashed/`kill -9`'d dev server leaves them looking hand-authored (and the scaffold's `.gitignore` is the only thing keeping them out of git). Combined fix with F5: closure-scoped `isDevServer`, plus cleanup-on-start of stale temp files. Effort S, risk low.
